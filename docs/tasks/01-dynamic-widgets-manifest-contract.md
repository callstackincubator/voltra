# 01 - Dynamic Widgets Manifest Contract

## Goal

Introduce the shared TypeScript contract and validation helpers for app.json-driven Dynamic Widgets manifests.

Voltra widget registration is moving away from whole-project discovery via `'use voltra'`. The native-side Dynamic Widgets model is:

- app.json declares which widgets exist.
- Each declared widget has a stable `id`.
- Each declared widget has an explicit `entry` path to the widget implementation file.
- The widget implementation module exports the widget as its default export.
- There is no `export` field in app.json.
- iOS and Android declarations are separate. The same `id` may appear on both platforms, but those are separate declarations.
- Prebuild validates platform config and writes `.voltra/manifest.ios.json` or `.voltra/manifest.android.json`.
- Metro reads the platform manifest and bundles only manifest-declared widgets.

## Expected Scope

Own the shared contract only. Do not rewrite Metro or platform prebuild emission in this task except where needed to expose shared types/helpers.

Primary files to inspect and likely update:

- `packages/expo-plugin/src/types.ts`
- `packages/expo-plugin/src/validation.ts`
- `packages/expo-plugin/src/index.ts`
- `packages/expo-plugin/src/validation.node.test.ts`
- Any package-local build/export metadata needed for these helpers to be consumed by `@use-voltra/ios-client`, `@use-voltra/android-client`, and `@use-voltra/metro`.

## Requirements

- Define a shared manifest shape for generated platform manifests. Suggested shape:
  - `version`: a small integer, start with `1`.
  - `platform`: `'ios' | 'android'`.
  - `widgets`: array of manifest widgets.
  - Each manifest widget contains at least `id` and normalized project-relative `entry`.
- Define the app config entry contract shared by iOS and Android widget configs:
  - `entry?: string` during rollout if needed to keep task 1 compiling, but the final feature requires `entry` for Dynamic Widgets.
  - Do not add an `export` field.
- Add validation for `entry`:
  - Must be a non-empty string.
  - Must be a relative path, not absolute.
  - Must not escape the project root after path normalization.
  - Must point to an existing file when `projectRoot` is supplied.
  - Must use a JS/TS source extension that Metro can import, such as `.js`, `.jsx`, `.ts`, `.tsx`, `.mjs`, `.cjs`.
- Add a helper to normalize entries to POSIX-style project-relative paths for manifest output.
- Keep existing widget metadata validation helpers intact for labels, ids, locale maps, and initial state paths.
- Tests must cover valid entries, missing entries where validation is expected, absolute paths, paths escaping the root, unsupported extensions, and missing files when `projectRoot` is supplied.

## Constraints

- Ignore backward compatibility. It is acceptable to require `entry` by the end of this feature.
- Do not reintroduce discovery via `'use voltra'`.
- Do not generate native platform code manually.
- Keep iOS and Android declarations separate.
- Prefer small, composable helpers that platform plugins and Metro can share.
- Avoid changing generated build artifacts unless the repository convention requires it. If build output is generated by package build scripts, prefer running the build instead.

## Reviewer Notes

- Check that error messages explain exactly which widget and field failed.
- Check that the manifest contract is platform-neutral but still distinguishes `platform`.
- Check that the type exports are available to platform plugin packages without circular dependencies.
- Check that same widget ids are only de-duplicated within a single platform config, not globally across platforms.

## Verification

Run the narrow package checks first:

```sh
pnpm --filter @use-voltra/expo-plugin test
pnpm --filter @use-voltra/expo-plugin typecheck
pnpm --filter @use-voltra/expo-plugin lint
```

Then run broader checks if touched exports affect other packages:

```sh
pnpm run typecheck
pnpm run lint
pnpm run test
```

Commit using a conventional commit message, for example:

```sh
git commit -m "feat: add dynamic widget manifest contract" -m "Defines the shared app.json entry validation and generated manifest shape used by platform plugins and Metro."
```
